# 基质扫描

## 目标与范围

第一阶段遍历武器基质背包，记录词条、等级、稀有度、锁定和弃用状态，提供最小列表页面。
不引入保留规则、武器评估、数量限制或自动标记。点击卡片与拖动只用于观察物品。

实现参考 EER commit `066d0e5b830fa06e0addbb52966fe6513b7e4eb1`。识别坐标以
1280×720、16:9 为基准，模板和布局由 EER 的 1080p 输入按 `2/3` 转换。
首期只识别简体中文游戏界面，OEA 界面提供中英文文案。

## 使用

1. 进入游戏「武器基质」背包，清除筛选，保持列表排序不变。建议先以 1280×720、关闭 HDR 验收。
2. 打开 OEA「基质扫描」，点击「开始扫描」。任务先回到列表顶部，然后逐枚识别并滚动。
3. 使用「停止」结束扫描，已取得的记录仍保留。切换 OEA 页面也会保留结果。
4. 展开单条记录的「查看详情截图」检查识别问题。截图仅裁剪详情面板。

报告范围是游戏当前显示的基质列表，扫描器无法检查筛选隐藏的物品。
「已遍历当前显示的基质列表」表示确认到达列表末尾，识别不完整的数量另行报告。
用户停止、页面改变、翻页位移不可信或达到翻页上限时保留部分结果。
结果只保存在当前应用会话中，新的基质扫描会替换上一轮报告。

普通浏览器中真实扫描按钮禁用，「模拟扫描」使用明确标注的演示数据。
Tauri 中模拟方式经过 Rust worker 和真实 IPC，但同样不验证游戏识别和鼠标操作。

## 实现与 contract

- `automation::essence_scan`：固定布局、详情识别、列表遍历、报告和 worker。
- `vision`：复用通用模板匹配、颜色和亮度统计，新增垂直滚动位移测量。
- `data::essence`：提供启动时已加载的词条目录与语义类别。
- `Controller`：接入全局自动化互斥运行时，持有当前/最近一次基质报告。
- `src/features/essenceScan/`：应用级前端报告投影，按运行身份接收事件。
- `src/pages/essence-scan.vue`：开始、停止、模拟和扫描记录列表。

启动复用 `start_automation`，请求为 `taskKind: "essenceScan"` 和 `workerType`。
停止与状态复用已有命令。`get_essence_scan_report` 返回当前/最近一次报告。
`essence-item-scanned` 推送单条记录，`essence-scan-progress` 推送阶段、数量和结束原因。
所有共享类型从 [model.rs](../src-tauri/src/automation/essence_scan/model.rs) 经 `ts-rs` 导出，
前端从 `src/shared/types/essenceScan.ts` 导入。

单条记录包含运行 ID、记录 ID、从顶部起算的行列、三项词条、稀有度、两种标记、
识别问题和详情截图。词条保留屏幕显示顺序，同时携带目录中的语义类别。
无法识别的身份、等级和标记以 `null` 表达。内容相同的两枚基质仍分别记录。

翻页每次拖动约三行，保留重叠画面，测量画面实际向上移动的距离，再推进绝对行游标。
不使用基质内容指纹去重。平坦或重复画面无法提供可信位移时停止，不猜测未扫描行的位置。

## 常量与模板来源

[layout.rs](../src-tauri/src/automation/essence_scan/layout.rs) 注明各屏幕常量对应的
EER `core/layout/res_1080p.py` 字段和缩放方式。词条 ROI、等级采样点、稀有度采样、
锁定/弃用按钮、滚动条与卡片中心都来自这份布局。

[recognition.rs](../src-tauri/src/automation/essence_scan/recognition.rs) 注明模板阈值来自
`attribute.py`、`abandon_lock_status.py`，等级亮度来自 `attribute_level.py`，
稀有度颜色来自 `essence_rarity.py`，滚动条亮点来自 `engine.py`。

`resources/templates/基质/` 包含 31 张词条模板和 5 张界面模板。
从 EER 的 `templates/generated/` 与 `templates/screenshot/` 转 RGB，按 `2/3` 四舍五入尺寸，
以双线性滤波缩放。模板源、参考 commit 与转换方式另见该目录 README。

OEA 的歧义差值、空槽亮度阈值、滚动内容区域、分步拖动和位移可信阈值属于本地策略，
代码分别注明来源及目的。尤其空槽判断沿用旧原型，不能当作 EER 的已验证识别结果。

## 验证与待验收

扫描接口测试使用确定的游戏能力 adapter，覆盖相同内容的两枚物品、未知字段、
不足整行的末页、重叠翻页和用户停止。真实 EER 模板嵌入人工截图验证模板管线、
不同语义顺序、等级、稀有度和标记。该人工截图不能证明游戏实机识别准确率。

当前没有可连接的 Windows 游戏环境。Windows 交叉编译、模拟界面及本地测试通过后，
仍需人工对照完整背包检查：总数、相同内容的不同物品、最后一行、锁定/弃用状态、
词条等级与翻页重叠。空槽识别、模板缩放后的容差、鼠标拖动惯性、滚动条端点和详情刷新等待
均需要 Windows 720p 实机校准。
