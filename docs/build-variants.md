# 构建形态的行为差异

术语定义见 [GLOSSARY.md](GLOSSARY.md)。

OEA dev 使用工作区中正在开发的资源。自更新会替换程序和资源，可能覆盖开发中的修改，或让正在调试的代码与资源失去对应关系。因此 OEA dev 禁用自更新，包括手动导入更新包，保护开发环境免受更新流程改写。

OEA release 的资源随程序独立分发，运行不依赖开发机器的工作区。更新作用于这份独立的应用副本，用户可以通过更新持续获得项目发布的修复和资源。

界面需要让人一眼辨认正在使用哪种形态。OEA dev 直接以产品名称的文字样式显示，避免配置中的发行版本号让测试代码看起来像已发布版本。OEA release 保留版本号，便于用户识别当前产物和判断更新。
